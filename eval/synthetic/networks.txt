Let us now look at how the transmission control protocol handles congestion. The sender keeps a congestion window that limits how many bytes can be in flight without an acknowledgement. When a connection starts, the window begins small and doubles every round trip time. This phase is called slow start, although the growth is actually exponential. When the window reaches the slow start threshold, the sender switches to congestion avoidance and increases the window by about one segment per round trip. This is additive increase. When a packet is lost, the sender reduces the window sharply, which is multiplicative decrease. If the loss is detected by three duplicate acknowledgements, fast retransmit sends the missing segment immediately, and fast recovery halves the window instead of starting again from one. If the loss is detected by a timeout, the situation is more serious, so the window falls back to one segment and slow start begins again. Together these rules let many connections share a link fairly. Modern variants such as cubic grow the window using a cubic function of the time since the last loss, which works better on long, fast networks.
