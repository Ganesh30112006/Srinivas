In this session we study deadlocks. A deadlock happens when every process in a set is waiting for a resource that is held by another process in the same set. Four conditions must hold at the same time for a deadlock to occur. The first is mutual exclusion, which means at least one resource cannot be shared. The second is hold and wait, where a process holds one resource while waiting for another. The third is no preemption, so a resource can only be released voluntarily. The fourth is circular wait, a closed chain of processes, each waiting for the next. We can prevent deadlock by breaking any one of these conditions. For example, we can impose a total ordering on resource types and require every process to request resources in increasing order, which removes circular wait. Deadlock avoidance is different. The system checks every request and grants it only if the resulting state is safe. The banker's algorithm does this using the maximum demand of each process, the current allocation, and the available resources. If no safe sequence exists, the request must wait. Detection and recovery is the third approach, where we allow deadlocks and then break them by terminating processes or preempting resources.
